## What to build

Replaces the design #14 first described, and ticket 3 of the closed PR
#13: those kept `thiserror` and, in the first version, moved the cause
into `source()`. This ticket adopts the shared standards in `rsb/rules`,
`standards/errors.md`, `standards/panics.md` and `standards/logging.md`,
which keep the whole trail in `{e}`, with the runtime pieces from
`rsb-errors` 0.1.1.

`rsb-errors` enters `[workspace.dependencies]` as
`{ git = "https://github.com/rsb/errors-rs", tag = "v0.1.1" }`, never an
SSH URL, with `snafu = "0.9"` and `tracing = "0.1"`; `thiserror` leaves
both crates.

`rsb-libraw-ffi`'s `Error` becomes a `snafu` enum with the same variants
and the same texts: `Init`, `Open { source: std::io::Error, location }`,
`PathNul`, `PathNotUtf8`, `Call { call, code, message }`. `Error::call`
and `ErrorCode` do not change. `Open`'s display stays
`cannot open file{location}: {source}`.

`rsb-libraw`'s `Error` struct, `with_source`, `.context()` and `ResultExt`
go. In their place one `snafu` enum in `crates/libraw/src/error.rs` with
one variant per failure the crate reports. Each carries `op: &'static str`
(the public method: `decode`, `decode_preview`, `decode_thumbnail`) and
`path: PathBuf`; a variant that wraps a lower error also carries `source`
and `#[snafu(implicit)] location: Loc`. Wrapping variants: `Init`,
`Open { exists: bool, .. }`, `Unpack`, `UnpackThumb`, `Process`,
`MakeImage`, `MakeThumb` (source `ffi::Error`) and `Jpeg` (source
`jpeg_decoder::Error`). Sourceless variants, for the checks this crate
makes and the `RawDecode` defaults: `Format { what }`,
`ThumbnailFormat { what }`, `Dimensions { what }`, `NoThumbnail`,
`NoPreview`. `ImageBuffer::new`, `from_rgb8` and `from_rgb16` return
`Dimensions`.

`Kind` stays as the public classification. `fn kind(&self) -> Kind` in
`error.rs` maps each variant, and for the ffi `Call` sources each
`ErrorCode`, to `Io`, `Unsupported`, `Corrupt` or `Resource` exactly as
`from_ffi` and `classify_open_file_error` do today, including the open-file
rule: an I/O code on a path that exists is `Corrupt`. A caller still
branches on `e.kind()`. `fn code(&self) -> &'static str` returns the dotted
variant path (`libraw.open`, `libraw.ffi.call`), one per variant.

Display strings begin with the operation, place `{location}` after it and
end with `{source}`, so `{e}` is one line from the public method to
LibRaw's text: the method as a verb with the path, the step, the ffi
text, then the cause. No type name and no category word. Locations are
on by default (`rsb-errors` 0.1.1), so each wrapping layer carries one
`(at file:line)`:

```
decode /photos/DSCF0001.RAF: open (at crates/libraw/src/adapter.rs:118): cannot open file (at crates/ffi/src/processor.rs:87): No such file or directory (os error 2)
```

After `rsb_errors::show_locations(false)` the same line has no `(at `
segments, and that form is the one the tests pin exactly:

```
decode /photos/DSCF0001.RAF: open: cannot open file: No such file or directory (os error 2)
```

The adapter replaces every `.map_err(from_ffi)` and `.context("...")` with
`.context(UnpackSnafu { op, path })`; `from_ffi` and
`classify_open_file_error` go, their mapping lives in `kind()`. The line
each public method prints for a missing file, an unreadable file and a
non-RAW file is shown to the owner as real output before the enum is
written, and the approved lines are pinned by
`crates/libraw/tests/error_line.rs`; `crates/ffi/tests/error_line.rs`
pins the ffi layer.

Panics: the root lint table becomes the one in `panics.md`, as
`rsb-errors`' `Cargo.toml` carries it, plus `let_underscore_must_use`
which `errors.md` requires; `rsb-libraw-ffi` repeats it without
`unsafe_code` and keeps `undocumented_unsafe_blocks`; `clippy.toml` becomes
`rsb-errors`'. `crates/ffi/build.rs` keeps its file-level allow, now for
`unwrap_used` only. `[profile.release]` states `panic = "unwind"` and
`overflow-checks = true`. No `extern "C"` callback exists in this
workspace today; when one is added it begins with `catch_unwind`, as the
standard and the check require.

Logging: `tracing` in `rsb-libraw-ffi`; `rsb-libraw` has nothing of its
own to log. `Processor` emits one `trace!` per LibRaw call, with the call
name and its duration: `logging.md` gives per-FFI-call detail `trace`.
Nothing logs at `info` or above; this is a library with no boundary
module.

Check: a workspace member `xtask`, with `cargo xtask errors` through
`.cargo/config.toml`, calls `rsb_errors::check::run` on the workspace root
with `ignore: ["crates/ffi/build.rs"]` (a build script must `println!`
cargo directives) and no dispatcher or boundary (a library has neither,
so `Config` names a path that does not exist), and exits 1 on any
finding. CI runs it after the tests. `engineering/never-crash.md` becomes
`errors.md`, `panics.md` and `logging.md`, each a pointer at the standard
naming this repository's check. `AGENTS.md` lists the xtask. The README's
architecture box, "Error handling" and "Error classification" describe
the enum, `kind()` and `code()`, and show the approved line.

Seams: `RawDecode`; `rsb_libraw::Error`; `Processor`.

## Acceptance criteria

- [x] `thiserror` appears in no `Cargo.toml`; `rsb-errors` at tag `v0.1.1`, `snafu` and `tracing` do; `ResultExt`, `.context(&str)`, `with_source`, `from_ffi` and `classify_open_file_error` are gone.
- [x] Each ffi `Error` and each `ErrorCode` gives the `Kind` its old mapping gave, pinned by tests through `kind()`; the integration tests in `crates/libraw/tests` keep their cases.
- [x] `{e}` for a missing file, an unreadable file and a non-RAW file is the line the owner approved, pinned by `crates/libraw/tests/error_line.rs` after `show_locations(false)`; by default each layer carries one `(at `. `crates/ffi/tests/error_line.rs` pins the ffi layer.
- [x] `source()` on `rsb_libraw::Error` returns the ffi or JPEG error and a typed match reaches `ErrorCode` without downcasting; `code()` covers every variant; both pinned by tests.
- [x] Root `Cargo.toml` has the `panics.md` lint table, `let_underscore_must_use` and the release profile; `cargo clippy --workspace --all-targets -- -D warnings` passes; every `expect` and `assert!` outside tests states its invariant.
- [x] `cargo xtask errors` passes on the branch and fails on a planted banned crate, a planted display string without `{source}`, a planted `.source()` outside `error.rs`, and a planted `warn!`.
- [x] `Processor` logs each LibRaw call at `trace` with its duration; `grep -rn 'info!\|warn!\|error!' crates` finds nothing.
- [x] `engineering/errors.md`, `panics.md` and `logging.md` point at the standards and name the check; `never-crash.md` is gone; `AGENTS.md` and the README reference the new names and the xtask.
- [ ] `cargo fmt --check`, clippy, `cargo test --workspace` and `cargo xtask errors` pass, and the `check` job passes on the PR.

Blocked by: `rsb/rules` standards landed. `rsb/errors-rs` `v0.1.1` tagged (locations on by default, errors-rs ticket #3).
