## What to build

`rsb-libraw`'s hand-rolled `Error` struct becomes one `thiserror` enum,
and a new rule, `engineering/errors.md`, says how errors are written here
and names the check that enforces it.

The enum has one variant per failure category, so callers match the
error itself instead of a separate `Kind`:

- `Io(ffi::Error)`: the file could not be read: missing, unreadable, or a
  path C cannot take.
- `Unsupported(Cause)`: the file was read, but its camera, format or
  thumbnail is not handled.
- `Corrupt(Cause)`: the file claims a supported format but its data is
  malformed.
- `Resource(ffi::Error)`: LibRaw ran out of memory or hit a limit.

`Cause` says what found the problem: `LibRaw(ffi::Error)`,
`Jpeg(jpeg_decoder::Error)`, or `Check(String)` for a check in this
crate (image dimensions, output format). Each variant's `Display` states
its own level only; the detail is reached through `source()`, so a caller
that walks the chain sees each fact once.

`Kind`, `location`, `with_source`, `.context()` and `ResultExt` go. The
LibRaw call name the context strings carried is already in the ffi
error's text (`libraw_unpack failed: ...`).

The mapping from LibRaw's codes to the four variants moves from the
adapter's `from_ffi` into `impl From<ffi::Error> for Error`, so the
adapter uses `?` where it called `.map_err(from_ffi)`. It is written by
hand: `#[from]` cannot send one source type to four variants. The
open-file rule (an I/O error on a path that exists is `Corrupt`) stays in
the adapter. `rsb_libraw::error` re-exports the ffi `Error` as
`LibRawError` and `ErrorCode`, so a caller can name what `source()`
returns without depending on `rsb-libraw-ffi`.

Every error keeps its category: each case that gave a `Kind` before gives
the matching variant now.

`engineering/errors.md` follows Lumen's: one `thiserror` enum per crate,
results not dropped, and no `anyhow`, `eyre`, other error crates or
`Box<dyn Error>`. Its check is a step in the `check` workflow that greps
every `Cargo.toml` for the banned crates and every `.rs` file for a boxed
`dyn Error`, and fails on a hit.

The README's "Error handling" example, "Error classification" table and
architecture box describe the enum.

Seams: `RawDecode`; `rsb_libraw::Error`.

## Acceptance criteria

- [ ] `crates/libraw/src/error.rs` defines `Error` and `Cause` with `thiserror`; `Kind`, `ResultExt`, `.context()`, `with_source` and `location` are gone from `crates/libraw`.
- [ ] Each ffi `Error` and each `ErrorCode` maps to the variant its old `Kind` named, pinned by tests through `Error::from`.
- [ ] The adapter has no `from_ffi` and no `.map_err` on a `Processor` call.
- [ ] `source()` on each variant reaches the underlying error, and no `Display` repeats its source's text.
- [ ] The integration tests in `crates/libraw/tests` keep their cases, matching variants instead of `Kind`.
- [ ] `engineering/errors.md` exists, and the `check` workflow has a step that fails when a `Cargo.toml` lists `anyhow`, `eyre`, `color-eyre`, `failure`, `error-chain` or `snafu`, or a `.rs` file boxes a `dyn Error`. The step fails on a planted hit of each kind.
- [ ] The README's architecture box, "Error handling" and "Error classification" describe `Error` and `Cause`.
- [ ] `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings` and `cargo test --workspace` pass, and the `check` job passes on the PR.
